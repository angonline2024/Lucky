# ระบบจองเลข 00–99 สำหรับ LINE OA

ลูกค้ากดจองผ่าน LINE OA (LIFF) หรือเว็บ → สรุปยอด → สแกน QR พร้อมเพย์ → ส่งสลิปในแชท → แอดมินยืนยันในหลังบ้าน
ไม่มี dependency ภายนอก ต้องการแค่ Node.js 18 ขึ้นไป

| หน้า | ที่อยู่ | ใช้ทำอะไร |
|---|---|---|
| ลูกค้า | `/` (เปิดผ่าน `https://liff.line.me/<LIFF_ID>`) | เลือกเลข จอง ดู QR ดูการจองของฉัน |
| หลังบ้าน | `/admin` | ผังเลข รายการจอง ราคา ตั้งค่า แชร์ QR |
| Webhook | `/webhook` | ตอบแชทอัตโนมัติ และแจ้งแอดมินเมื่อลูกค้าส่งสลิป |

## 1. ลองในเครื่องก่อน (ไม่ต้องมี LINE)

```bash
DEV_MODE=1 npm start
```
- ลูกค้า: http://localhost:3000/?as=userA (เปลี่ยน `as=` เพื่อจำลองลูกค้าคนอื่น)
- หลังบ้าน: http://localhost:3000/admin รหัสผ่านคือ `dev`
- โหมดนี้ไม่ตรวจ LINE login และไม่ส่งข้อความจริง ห้ามใช้ขึ้นระบบจริง

## 2. ตั้งค่า LINE Developers

ทำทั้งหมดใน Provider **เดียวกัน** (สำคัญ เพื่อให้ userId ตรงกันทุก channel)

1. **Messaging API channel** (คือ LINE OA ของคุณ): เปิด Messaging API ใน LINE OA Manager
   - คัดลอก *Channel secret* → `LINE_CHANNEL_SECRET`
   - ออก *Channel access token (long-lived)* → `LINE_CHANNEL_ACCESS_TOKEN`
   - ตั้ง *Webhook URL* = `https://โดเมนของคุณ/webhook` แล้วเปิด Use webhook กด Verify ต้องขึ้น Success
   - ปิด "ข้อความตอบกลับอัตโนมัติ" ใน OA Manager เพื่อไม่ให้ตอบซ้ำกับระบบนี้
2. **LINE Login channel**: สร้างใหม่ใน Provider เดิม
   - คัดลอก *Channel ID* → `LINE_LOGIN_CHANNEL_ID`
   - แท็บ LIFF กด Add: Size = **Full**, Endpoint URL = `https://โดเมนของคุณ/`, Scope = **openid** และ **profile**
   - ได้ *LIFF ID* → `LIFF_ID`
   - แท็บ Basic settings เลือก Linked OA เป็น OA ของคุณ และตั้ง Add friend option เป็น Normal หรือ Aggressive เพื่อให้ลูกค้าเป็นเพื่อนกับ OA (ระบบจึงส่งข้อความหาลูกค้าได้)
   - เปลี่ยนสถานะ channel เป็น **Published**
3. **Rich Menu**: ใน OA Manager เพิ่มปุ่มแบบ Link ใส่ `https://liff.line.me/<LIFF_ID>` ลูกค้ากดแล้วเข้าหน้าจองได้ทันที
4. **userId ของแอดมิน** (ไม่บังคับ ใช้รับแจ้งเตือนเมื่อมีการจอง): ดู *Your user ID* ที่หน้า Basic settings ของ channel แล้วใส่ใน `ADMIN_LINE_USER_IDS` คั่นด้วยจุลภาค แอดมินต้องเป็นเพื่อนกับ OA ด้วย

## 3. ติดตั้งบนเซิร์ฟเวอร์

ต้องเป็นที่ที่รัน Node ได้ มี **HTTPS** และมี **ดิสก์ถาวร** (ข้อมูลเก็บในไฟล์ `DATA_FILE`) เช่น VPS หรือบริการที่มี persistent volume

```bash
cp .env.example .env        # แล้วแก้ค่า
set -a; . ./.env; set +a
npm start
```
หรือใช้ Docker: `docker build -t number-booking .` แล้วรันด้วย `-v /ที่เก็บข้อมูล:/data -p 3000:3000 --env-file .env` และวาง reverse proxy ที่ให้ HTTPS (เช่น Caddy, nginx) ไว้ด้านหน้า

ข้อควรรู้
- รันได้ **ครั้งละ 1 instance เท่านั้น** (ข้อมูลเป็นไฟล์เดียว) เหมาะกับงานระดับ 100 เลขและผู้ใช้หลักร้อย
- สำรองข้อมูลโดยคัดลอกไฟล์ `db.json` เป็นระยะ
- ตั้ง `ADMIN_KEY` ให้ยาวและเดายาก ระบบจะไม่เริ่มทำงานถ้าสั้นกว่า 12 ตัวอักษร

## 4. ตั้งค่าครั้งแรก

เข้า `/admin` → แท็บ **ตั้งค่า**: ใส่พร้อมเพย์ (เบอร์ 10 หลัก หรือเลข 13 หลัก) ชื่อบัญชี และเวลาถือเลขรอชำระ จากนั้นแท็บ **ราคา** ปรับราคาเริ่มต้น (ตอนนี้ 100 บาท) หรือตั้งเป็นช่วง/รายเลข
สแกน QR จากแท็บ **แชร์** หรือกดปุ่มใน Rich Menu เพื่อลองจองเอง แล้วโอนยอดเล็ก ๆ ทดสอบกับบัญชีจริงก่อนเปิดใช้

## 5. การทำงาน

- ราคาคำนวณที่เซิร์ฟเวอร์ ลูกค้าแก้ราคาเองไม่ได้ และราคาที่จองแล้วไม่เปลี่ยนตามการแก้ราคาภายหลัง
- กันจองซ้ำ: ถ้ามีคนจองตัดหน้า ระบบแจ้งและนำเลขนั้นออกจากรายการให้
- ตั้ง "เวลาถือเลขรอชำระ" แล้ว เลขที่ไม่ชำระตามเวลาจะถูกปล่อยว่างอัตโนมัติและแจ้งลูกค้า (0 = ไม่หมดเวลา)
- ลูกค้าเห็นเฉพาะสถานะของเลข ชื่อและเบอร์เห็นได้เฉพาะหลังบ้านและเจ้าของการจองนั้น
- ระบบไม่ตรวจยอดเงินเข้าบัญชีให้ แอดมินต้องเทียบสลิปแล้วกด "ยืนยันชำระ"
